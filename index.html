Jornada 1 · Antecipação de recebíveis

Como a Blip enxerga no WhatsApp

O canal é exclusivo para antecipação: o menu traz só antecipar agora (pontual) e antecipação recorrente. O cliente escolhe um CNPJ ou todos de uma vez, e se não concordar com a taxa, um Agent especialista negocia dentro da margem que vem da API.

Escolha uma das três simulações. Todas começam pelo mesmo menu.

    Recursos do WhatsApp

    • Template ativo disparado a partir do CRM quando há saldo para antecipar.
    • Botões de resposta rápida no menu e nas confirmações: antecipar agora, recorrente, confirmar, negociar.
    • Mensagem de lista para os CNPJs (com a opção “Todos os CNPJs”) e para o dia da recorrência.
    • Agent negociador que trabalha com a taxa base e a margem da API, com transbordo para humano.
    • Integração em bastidores com a API do parceiro na validação, no saldo, na solicitação e na recorrência.

    Mais de um número por cliente

    O mesmo cliente pode ter mais de um celular autorizado, por exemplo do sócio e do financeiro, e qualquer um deles pode antecipar por aqui.

    O cadastro de cada número é feito sempre pelo portal do parceiro, como no fluxo. O WhatsApp só valida o número, não cadastra.

    Caminhos alternativos (fora da simulação)

    • Entrada ativa pelo CRM: o cliente recebe a notificação “Você tem saldo para antecipar”, toca em “Antecipar agora” e segue direto para a validação.
    • Número não autorizado: “Não encontramos este celular entre os usuários autorizados. Para antecipar pelo WhatsApp, acesse o portal do parceiro, cadastre este número nos seus dados de acesso e volte aqui.”
    • Sem saldo a antecipar: informa o cliente e encerra.
    • “Sim, outro CNPJ”: volta para a lista de CNPJs.
    • Negociação aceita: com a taxa acordada, segue para a solicitação (ou para o cadastro da recorrência).

    Jornada 1 · Fluxo da jornada

    O fluxo por trás da conversa

    Duas entradas levam ao mesmo menu: o cliente pelo atendimento ou o CRM do parceiro pela notificação ativa. Depois da validação e do saldo, o fluxo se divide entre antecipação pontual e recorrente, e a negociação de taxa entra quando o cliente pede.

    Pontual ou recorrente · 4 chamadas de API
    Subprocesso · Jornada de recorrência

    Antecipação recorrente

    Com os CNPJs escolhidos, o cliente define o dia do mês e recebe o alerta de taxas antes de confirmar. Se pedir negociação, entra o mesmo Agent negociador.

    1 chamada de API
    Subprocesso · Negociação de taxa

    Agent negociador e transbordo

    Até duas tentativas de retenção pelo Agent. Na terceira recusa, o atendimento humano do parceiro assume com todo o histórico.

    Taxa e margem vêm da API · 2 retenções
    🤝
    Premissas do Agent negociador
    1. Usa sempre a taxa base e a margem retornadas pela API do parceiro, nunca valores fixos no bot.
    2. Começa pela taxa que favorece o parceiro.
    3. Na recusa, entende o motivo e faz uma oferta melhor, dentro da margem.
    4. Se o cliente recusar de novo, faz a última oferta com a melhor taxa da margem.
    5. Na terceira recusa, transborda para um humano, sem nova oferta automática.

    Jornada 2 · Negociação de preço de combustível

    Como a Blip enxerga no WhatsApp

    O disparo leva só o básico (telefone, ID da negociação e nome). Quando o gerente demonstra interesse, a API traz os combustíveis, volumes e preços pelo ID. O aceite acontece em um toque e é formalizado por áudio. Só depois da confirmação o CRM é atualizado.

      Recursos do WhatsApp

      • Template aprovado disparado pelo Blip Marketing ou direto do CRM do parceiro (integrado), com o nome do gerente como variável.
      • Consulta via API pelo ID da negociação, depois que o gerente demonstra interesse.
      • Botões de resposta rápida para aceitar ou falar com um consultor.
      • Mensagem de áudio como confirmação formal do acordo.

      Mais de um combustível por negociação

      Uma mesma negociação pode envolver vários combustíveis, como etanol, diesel e gasolina, cada um com seu potencial e seu preço.

      O bot apresenta todos e o Agent de negociação precisa negociar cada um deles, inclusive quando o gerente aceita só parte da proposta.

      Caminhos alternativos (fora da simulação)

      • Não aceitou ou “Falar com consultor”: Agent de negociação explica as vantagens e pergunta de novo.
      • Segunda tentativa sem aceite: encerra a conversa.
      • Áudio não confirmado: o bot pede um novo áudio.
      Jornada 2 · Dependências de API

      O que a empresa parceira precisa disponibilizar

      A mensagem inicial sai pelo mailing do analista ou direto do CRM do parceiro, levando só telefone, ID da negociação e nome. A API do parceiro entra em dois momentos: consulta os dados da negociação pelo ID quando o gerente demonstra interesse e registra o acordo fechado no fim.

      Pré-requisito para o projeto

      Sem a API de consulta, o bot não tem os combustíveis, volumes e preços para apresentar. Sem a API de atualização, o acordo é aceito na conversa mas não chega ao CRM do parceiro. As duas precisam estar em homologação para validar a jornada de ponta a ponta.

      Ponto de atenção: disparo integrado ao CRM

      A integração do disparo da mensagem inicial deve ser feita pela empresa parceira. No discovery vimos que hoje são dois sistemas diferentes: um em que a solicitação de negociação chega ao time de analistas e outro em que a analista busca o número do posto. Para disparar direto do CRM, os dois dados (a negociação e o celular do gerente) precisam estar juntos no momento do disparo, unificando ou integrando os sistemas. Enquanto isso não acontece, o disparo segue pelo mailing do analista.

      Jornada 3 · Credenciamento de postos

      Como a Blip enxerga no WhatsApp

      O convite chega com imagem, as vantagens vêm em seguida e o cadastro é feito num formulário nativo do WhatsApp. O posto é credenciado via API ao final.

        Recursos do WhatsApp

        • Template com imagem disparado pelo Blip Marketing a partir do mailing ou direto do CRM do parceiro (integrado).
        • Botões de resposta rápida para demonstrar interesse e aceitar as condições.
        • WhatsApp Flows: formulário dentro da conversa com nome do posto, CNPJ, endereço, e-mail e telefone.

        Caminhos alternativos (fora da simulação)

        • Não quer se cadastrar ou “Falar com atendente”: Agent de vendas explica as vantagens e pergunta de novo.
        • Segunda tentativa sem interesse: encerra a conversa.
        Jornada 3 · Dependências de API

        O que a empresa parceira precisa disponibilizar

        O convite pode partir do mailing do analista ou direto do CRM do parceiro, integrado à Blip. A API do parceiro recebe os dados preenchidos no formulário e credencia o posto.

        Pré-requisito para o projeto

        Sem a API de cadastro disponível em homologação, o formulário é preenchido mas o posto não é credenciado, e a mensagem de boas-vindas não pode ser confirmada.
